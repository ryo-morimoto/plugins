# Widening options

A single explanation attracts attachment the moment it looks satisfying, and from then on it steers what you notice. Decisions framed as "whether or not" fail more often than those with real alternatives. So widen first, at every layer, then narrow.

## Layers to widen
1. **The question**: generalise it, specialise it, find an analogous one, drop one condition, work backwards.
2. **Propositions**: hold three or more rivals. Always include the opposite of the favourite.
3. **Mode**: name at least two modes from `axes-purpose.md` that could apply.
4. **Scenario**: use a morphological box (below).
5. **Variable values**: sweep, do not jump between two extremes.
6. **Resolutions**: list several before picking (`axes-outcome.md`, axis 10).
7. **Next moves**: offer the user three or more.

## Techniques
- **Rival propositions**: design each operation so that some rival dies whatever the outcome. A conclusion that excludes nothing is not secure.
- **Morphological box**: list the independent dimensions of the problem and the values each can take; lay out the combinations; strike those that cannot coexist; pick scenarios far apart in what remains. It reaches corners intuition skips.
- **Vanishing options**: suppose none of the current options is allowed. What else?
- **Evidence table**: rivals as columns, results as rows. Work to reject, not to confirm. A row consistent with every column has no diagnostic value.
- **Parallel drafts**: sketch several scenarios before judging any; compare them side by side.

## Limits
- Aim for one or two more options than feels natural, not an unbounded list. Too many stalls the user.
- Widening is not a conclusion. After widening, narrow by elimination and say what was cut.
- If rivals are hard to invent, the box and the question layer are where to look; evidence tables do not create hypotheses.
