# 地図の画面の検査（veriss）

`map.html` を、[mizchi/veriss](https://github.com/mizchi/veriss)（描画せずに、CSS と DOM から、全画面幅のレイアウト・アクセシビリティ・CSS の誤りを検査する）にかけます。

```sh
VERISS=<veriss の clone>/packages/veriss/src \
CHROME=<ヘッドレスの Chromium> \
./check.sh
```

`fixture/maps/all-states/` の地図（7 つの状態と、軸の札の組み合わせをすべて含む）を生成し、3 つの状態 × 4 つの部品 × 4 つの幅の帯、計 48 通りを検査します。終了コードは、許していない指摘が 1 つでもあれば 1 です。

## 準備

- veriss は npm に公開されていません。`git clone https://github.com/mizchi/veriss` し、`pnpm install --ignore-scripts` します。確かめたのは commit `28c561f` です。veriss の LICENSE は、この時点でありません（手元での検査にだけ使い、このリポジトリには含めません）。
- **veriss の不具合への手当てが要ります。** 押せる範囲の大きさ（target-size）の検査は、縦方向の大きさがわからない箱（縦方向の検査をしないとき、すべての箱）で `TypeError` を出して止まります（`src/layout/accessibility.mjs` の `undersized` が `row.block` の `null` を引き算に渡す）。手元では、縦方向の大きさがわからない対象を「判定不能」に回し、隣の対象は「どこでも小さいかもしれない」とみなす（例外を誤って認めない側）ように直して検査しました。上流で直るまでは、同じ手当てが要ります。
- Chromium は、描画したあとの DOM を書き出すのに使います（`map.html` は JavaScript で DOM を組み立てるため）。

## 検査のしかた（`veriss_map.mjs`）

- `<script>` を除き、`style` 属性は要素ごとの id の規則に移します（id の規則は、ページのクラスの規則より優先されるので、優先順位は変わりません）。
- `<code>` は、veriss の HTML の読み込みが扱わないため、検査のためだけに `<span>` に置き換えます。
- 1 ページを一度に検査すると、veriss の作業量の上限を超えます。そのため、ヘッダー、軸の札、地図の表、候補の欄に分け、画面の切り替わり（600px、1000px）で幅の帯も分けます。`main` の列の幅は中身に依存せず、地図の欄の中は縦に並べているだけなので、分けても各部品の幅は変わりません。
- 信頼する前提として、文字の箱に「どこでも折り返せる、最小幅 24px」を与えます。`body` の `overflow-wrap: anywhere` により、文字の箱の最小幅は最も幅の広い 1 文字になり、ページで最大の文字（24px）以下です。折り返しの宣言と CSS の一致は、veriss が自分で確かめます。地図の表には「横にスクロールする」を与えます。
- スクロールバーは、重ねて表示される環境（0px）と、場所を取る環境（17px）の両方を宣言します。

## 許している判定不能

**押せる範囲の大きさ（WCAG 2.5.8、24px）だけ**です。決めるには縦方向の大きさが要り、veriss の縦方向の検査は、すべての文字の箱に正確な高さの前提を求めます。文字の高さはフォントと折り返しで変わるので、正直には与えられません。地図のセルと候補の項目は、横幅が 120px 以上あるので、横方向では満たしています（縦方向は未確認）。
