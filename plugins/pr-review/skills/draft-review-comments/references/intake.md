# 気づきの取り込み方

気づき（finding）の元になる情報を、`records.md` の書式の記録にする方法です。どの経路でも、次の原則は同じです。

- **本文は原文のまま**にします。
- 言い換えてよいのは、`title` と `location` だけです。言い換えは、判断の根拠にしません。
- 本文を書き換えると、`body_hash`（本文の SHA-256）が合わなくなります。

## (a) pr-tour の JSON 書き出し（v1）

推奨の経路です。pr-tour が書き出した JSON（`schemaVersion` が 1、`kind` が `pr-tour-review`）を、スクリプトで取り込みます。

```
python3 <skill>/scripts/import-findings.py --store "${XDG_DATA_HOME:-$HOME/.local/share}/pr-review" --repo <対象のリポジトリ> --from <書き出した JSON> [--series <まとまりの名前>] [--created-by <名前>] [--dry-run]
```

`<skill>` は、`SKILL.md` があるディレクトリです（`SKILL.md` を参照）。

- 各コメントには、`commit`（40 桁の 16 進）と `code`（選んだ行の原文）が要ります。無いものは、取り込みません。
- 取り込む前に、各コメントの `startLine`〜`endLine` を、`--repo` のリポジトリの `commit` 時点の `path` と照合し、`code` と一致するかを確かめます。**一致しないコメントが 1 件でもあれば、全件を報告して何も書かず、終了コード 2 で止まります**（行の位置が、静かにずれたまま記録されるのを防ぐため）。改行の CRLF と、末尾の改行の違いは、同じとみなします。
- `commit` が手元のリポジトリに無いと、読めずに止まります。先に `git fetch` してください。
- 先に `--dry-run` で、作られる予定を確かめます。照合は、`--dry-run` でも行います（読み取りだけです）。`--dry-run` が示す id は、実際の取り込みで変わります。
- 同じ PR で、`origin_ref`（元のコメントの id）が同じ気づきが既にあれば、作らずに「スキップ」と報告されます。本文が違うときは「衝突」と報告され、上書きはされません。
- 既存のファイルと混ぜない別のディレクトリを `--store` に指定することを勧めます（配置の関係が未決のため。README の「現状と制限」を参照）。
- 2026-11-20 に、実物の pr-tour の書き出し（ある実プロジェクトの PR、コメント 4 件）で、`--dry-run`、取り込み、`validate-records.py`、再実行（全件スキップ）が通りました。`code` の照合も、4 件とも一致しました。取り込みを直す必要は、ありませんでした。
- 合成データとの違い: ID が UUID です（合成データは `c-001`）。4 件とも、`side` は `right` で、1 行だけの選択で、本文と `code` に改行がありません。`code` に、タブと日本語の文字が入っています。
- 実物で、まだ確かめていないもの: `side` が `left` のコメント、複数行の選択、複数行の本文や、先頭が改行の本文、CRLF。これらは、合成データだけで確かめています。

## (b) pr-tour の「Copy for AI」の Markdown

スクリプトの対象外です。手で気づきを作ります。

1. コピーした Markdown の本文を、原文のまま `finding.md` の本文にします。
2. `body_hash` に、その本文の SHA-256（16 進）を書きます。本文は、前後の改行を除いたものです。
3. そのほかの項目は、`records.md` の「finding」の表に従って書きます。`origin` は、書いた人が人なら `"human"` です。

SHA-256 は、たとえば次のように出せます。

```
printf '%s' "<本文>" | shasum -a 256
```

本文を複数行で扱うときは、本文だけをファイルに保存して、`shasum -a 256 <ファイル>` で出します。前後の改行が入らないように気をつけます。

## (c) `/code-review`（Claude Code の機能）の出力

**この取り込みは、実際の出力で検証されていません。**

- 利用者が貼ったテキストを、原文のまま本文にします。
- `origin` は `"detector"` にします。
- `confidence` は、出力に確からしさの表示があればそれに合わせます。なければ `"unknown"` にします。
- `/code-review` は、`--comment` を付けずに使います。投稿は、この plugin の承認の関所（人の承認のあと、人が投稿する）を通すためです。

## (d) 自由な文章

利用者が書いた文章、チャットでのやりとりなど、上の形式に当てはまらない気づきです。

- 文章を、原文のまま本文にします。
- `origin` は、書いたのが人なら `"human"` です。
- 場所が分かるときだけ、`location` を書きます。分からなければ `null` にします。

## 言い換えを置く場所

要約や短い見出しがほしいときは、`title` に書きます。長い言い換えは、記録には残さず、会話の中で扱います。言い換えを、判断の根拠にしません。
