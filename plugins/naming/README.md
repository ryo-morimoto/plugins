# naming

> **検証中（experimental）です。** より良いスコープに組み替える可能性が高く、名前・構成・台帳の書式は、予告なく変わります。

## 目的

名前を付けるか、何と呼ぶか、既存の名前を変えるかを、Zach Tellman の方法（*Elements of Clojure*）で決めます。一般的な助言（説明的な名前、小さな関数）とは違う既定を持ちます。

範囲（ファイル、モジュール、ブランチ）の名前をまとめて直す依頼では、1 回の呼び出しで、次の見直しで指摘が出ない状態を目指します。手作業で名前を拾うと見落とすので、名前を機械的に数え上げ、自分の改名が残した名残を検索し、指摘がなくなるまで繰り返します。判定は台帳に残し、次の呼び出しが根拠なく変え直さないようにします。

## インストール

```
/plugin install naming --marketplace ryo-morimoto/plugins
```

インストールは、まだ試していません。claude.ai に同じ `tellman-naming` を上げていると、2 つが並んで見えます。どちらか一方にしてください。

## 構成

| 部品 | 種類 | 内容 |
| --- | --- | --- |
| `tellman-naming` | skill | 案内役の `SKILL.md` と、判定の規則（`core/`）、言語ごとの既定（`packs/`） |
| `core/audit.md` | 参照 | 範囲をまとめて直す手順。依頼の確定 → 規則を全部読む → 台帳を読む → 数え上げ → 全件の判定 → 適用と繰り返し → 台帳に記録 → 別の文脈からの見直し |
| `core/decisions.md` | 参照 | 判定の台帳（`naming-decisions.md`）の書式と規則 |
| `core/review.md` | 参照 | 既存の名前の判定表。結論は、削除・統合・変える・残す |
| `scripts/inventory.py` | script | 名前の数え上げ。`--collisions`（同じ語が別の種類に使われている）、`--unused`（一度しか出てこない）、`--words`（古い語の残り） |

`inventory.py` は Python 3.11 以上の標準ライブラリだけで動きます。Python は構文木で、JS・TS・CSS・HTML・JSON・TOML・YAML・Markdown・Rust・Clojure は正規表現で拾います。正規表現の部分は、珍しい書き方を見落とすことがあります。テスト: `python3 -m unittest discover -s plugins/naming/tests`

## 設計の根拠

元の `tellman-naming`（claude.ai の plugin から同期していたもの）を、1 つのコードに 4 回かけて、ようやく指摘が出なくなりました。その原因と、より良い全体の設計を、思考実験と試験で調べました（記録: [thought-experiments の experiments/2026-11-21-naming-skill-one-pass.md](https://github.com/ryo-morimoto/thought-experiments/blob/e13398d/experiments/2026-11-21-naming-skill-one-pass.md)）。

- 取りこぼしの多くは、依頼の曖昧さと、規則のファイルを読み飛ばしたことによるものでした。依頼を明示して規則を全部読むと、1 回で CSS の変数まで見ました（3 回の試行）。
- 同じ条件でも、新しい名前の選び方は試行ごとに割れました（判定が割れやすい 25 個のうち一致 44%）。規則は「その名前ではいけない理由」は出しますが、次の語を 1 つには決めません。そのため、台帳で判定を固定します。
- 修正後の skill を 1 回かけると 34 件を直しましたが、別の文脈からもう一度かけると、さらに 5 件が見つかりました。自分の最後の繰り返しは独立しないので、別の文脈からの見直しを既定にしています。
- 台帳に「残す」をまとめて記録すると、見落としが次の呼び出しにも引き継がれました。そのため、検討した判定表の行を書いた「残す」だけを拘束力のある判定にしています。

元の skill から変えた点:

- 書き方の傾向（周りのコードの多数派）に合わせるのは、依頼されたときだけ。既定では規則だけで判定する。
- 判定表に「要るか → 削除」と「同じものの別名 → 統合」の行を足した。
- 「〜して」の依頼は、報告だけでなく適用まで行う。未公開の名前は、外から見える名前でも安い内部名として扱う。
- 範囲をまとめて直す手順（`core/audit.md`）、判定の台帳（`core/decisions.md`）、数え上げのスクリプトを足した。

この版を、元の題材でもう一度試しました（2026-11-21）。

- 手順 1〜7 を 1 回かけると、前の版が 2 回続けて見落とした `checked` と `next` を変えました（各 1 回の試行）。「残す」はまとめて記録されませんでした。
- 手順 8（別の文脈からの見直し）は、さらに 7 件の見落としを見つけました。台帳の判定をひっくり返したものは 0 件で、7 件とも記録のない名前でした。手順 1〜7 だけでは 1 回で直しきれないので、手順 8 は省けません。手順 8 の指摘を直したあと、もう一度見直して 0 件になるかは試していません。

## 未確認のこと

- 題材は 1 つのリポジトリの 6 ファイルだけです。ほかのコードで同じ結果になるかは分かりません。
